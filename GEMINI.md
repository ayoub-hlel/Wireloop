# Arduino Workflow Builder - Developer Guide

## Project Overview
Arduino Workflow Builder is a visual programming platform for Arduino development and electronics education. It allows users to create Arduino programs using a drag-and-drop block interface (Blockly) and provides real-time circuit simulation and code generation.

### Core Technologies
- **Frontend**: [SvelteKit](https://kit.svelte.dev/) (using Svelte 5 runes) with TypeScript.
- **Styling**: [Tailwind CSS 4](https://tailwindcss.com/) and [Shadcn-Svelte](https://shadcn-svelte.com/).
- **Backend/Database**: [Convex](https://convex.dev/) for real-time data synchronization and backend functions.
- **Authentication**: [Clerk](https://clerk.com/) for user management.
- **Block Editor**: [Google Blockly](https://developers.google.com/blockly) for the visual programming interface.
- **Graphics/Simulation**: [SVG.js](https://svgjs.dev/) for the virtual circuit simulation.
- **Testing**: [Vitest](https://vitest.dev/) for unit and integration testing.

## Building and Running

### Prerequisites
- Node.js 18+
- Convex CLI (`npm install -g convex`)
- Clerk account and API keys

### Environment Setup
The project uses a dynamic environment configuration. `src/env.ts` is generated by copying files from the `env/` directory during the development and build processes.

```bash
# Development (copies env/env.development.ts to src/env.ts)
npm run dev

# Build for Staging (copies env/env.staging.ts to src/env.ts)
npm run build
```

### Key Commands
- `npm run dev`: Starts the Vite development server.
- `npm run build`: Builds the project for static hosting (using `@sveltejs/adapter-static`).
- `npm run preview`: Previews the production build locally.
- `npm test`: Runs unit tests using Vitest.
- `npm run test-coverage`: Runs tests and generates a coverage report.
- `npm run check`: Runs Svelte-check and TypeScript type checking.
- `npx convex dev`: Starts the Convex development environment (required for backend functionality).

## Architecture & Conventions

### Directory Structure
- `src/blocks/`: Custom Blockly block definitions, grouped by category (e.g., `led`, `sensors`, `logic`).
- `src/core/`: Core logic for Blockly integration, microcontroller simulation, and virtual circuits.
- `src/components/`: Reusable Svelte components, including UI and domain-specific parts.
- `src/stores/`: Svelte stores for managing global application state.
- `src/helpers/`: Utility functions and managers (e.g., offline manager, data integrity).
- `convex/`: Backend schema and functions (queries/mutations).
- `static/`: Static assets, including images, fonts, and Arduino libraries.

### Development Conventions
- **Svelte 5**: Use Svelte 5 runes (`$state`, `$derived`, `$effect`, `$props`) for reactivity.
- **TypeScript**: Strictly type all new code. Use interfaces and types defined in `src/types/` or `convex/schema.ts`.
- **Blockly**: When adding new blocks, follow the modular structure in `src/blocks/`. Each block category should have its own directory with block definitions and code generation logic.
- **Styling**: Use Tailwind CSS utility classes and Shadcn-Svelte components for UI consistency.
- **Database**: All persistent data should be managed via Convex queries and mutations in the `convex/` directory.
- **Testing**: Add Vitest tests for new logic, especially for code generation and state management.

## Deployment
The project is configured for static hosting using `@sveltejs/adapter-static`. The build output is located in the `build/` directory.
- Ensure `src/env.ts` is correctly configured for the target environment before building.
- Convex functions must be deployed to the corresponding Convex environment (`npx convex deploy`).
